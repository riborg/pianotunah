# Mac-appen uppdaterar sig själv från GitHub Releases med Sparkle, självsignerad och utan sandlåda

Mac-appen ska uppdatera sig själv när en ny version släpps, och det finns inget Apple Developer-konto. Den använder Sparkle 2 med flödet som en fil på den senaste GitHub-releasen (`releases/latest/download/appcast.xml`), så förhandsreleaser når den aldrig, om inte *Hämta betaversioner* är påslaget: då läser den ett betaflöde med det nyaste bygget, `beta.xml` på grenen `appcast`, som release-jobbet håller (tillagt efter v1.13.0). Uppdateringar kontrolleras med Sparkles EdDSA-signatur. Appen signeras i CI med ett självsignerat certifikat, giltigt i 10 år och sparat som hemlighet, eftersom ad hoc-signering eller ett förnyat certifikat ger appen en ny identitet, och macOS då skulle fråga om mikrofonen igen. GitHub-releasen förblir ett utkast tills Mac-jobbet har laddat upp zip-filen och appcasten, så att `latest` aldrig pekar på en release utan flöde. Utan notarisering måste första starten tillåtas en gång under Integritet och säkerhet. Appen körs utan App Sandbox och utan hardened runtime: Sparkle i sandlådan kräver extra installationstjänster, och hardened runtime spelar bara roll för notarisering. En egen uppdaterare mot GitHubs API valdes bort; Sparkle sköter redan nedladdning, kontroll, utbyte och omstart. Om appen någon gång delas är nästa steg ett Developer ID med notarisering, och flödet förblir detsamma. [English](0004-mac-app-updates-itself-from-github.md). Se steg 6 i [docs/macos-port.sv.md](../macos-port.sv.md).
