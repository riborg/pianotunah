# The Mac app updates itself from GitHub Releases with Sparkle, self-signed and without the sandbox

The Mac app should update itself when a new version is released, and there is no Apple Developer account. It uses Sparkle 2 with its feed as an asset on the latest GitHub Release (`releases/latest/download/appcast.xml`), so pre-releases never reach it, unless *Get beta versions* is on: then it reads a beta feed of the newest build, `beta.xml` on the `appcast` branch, which the release job keeps (added after v1.13.0). Updates are verified with Sparkle's EdDSA signature. The app is signed in CI with one self-signed certificate, valid for 10 years and kept as a secret, because ad-hoc signing or a renewed certificate gives the app a new identity, and macOS would ask for the microphone again. The GitHub Release stays a draft until the Mac job has uploaded the zip and the appcast, so `latest` never points at a release without a feed. Without notarization the first launch must be allowed once under Privacy & Security. The app runs without the App Sandbox and without the hardened runtime: Sparkle in the sandbox needs extra installer services, and the hardened runtime only matters for notarization. Writing an own updater against the GitHub API was rejected; Sparkle already does download, verification, replacement and relaunch. If the app is ever shared, the next step is a Developer ID with notarization, and the feed stays the same. [Svenska](0004-mac-app-updates-itself-from-github.sv.md).
